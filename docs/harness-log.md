# Harness log

One entry per merged PR: what the coding agent got wrong or needed to be told, and what changed in the harness so it won't happen again. See the [walking skeleton PRD](prd/walking-skeleton.md#harness-log).

| PR  | What went wrong                                                                                                                                                                                                                   | Harness change                                                                                                                                                                           |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| #19 | Q80 said "React Router v7", but the current major is v8, so the record was wrong before any code existed.                                                                                                                         | `AGENTS.md`: decision records name tools, not versions.                                                                                                                                  |
| #19 | The PR had no screenshots, so reviewers couldn't see the change.                                                                                                                                                                  | `AGENTS.md`: PRs that change what a client shows include phone and desktop screenshots from the running app.                                                                             |
| #19 | The review had to ask for `~/` imports, `project.json` instead of an `nx` field in `package.json`, and `src/` instead of `app/`.                                                                                                  | oxlint `import/no-relative-parent-imports` for `apps/**`; `AGENTS.md`: apps import through a `~/` alias, and Nx projects keep their config in `project.json` and their source in `src/`. |
| #23 | A scripted edit put an `if:` inside a `run:                                                                                                                                                                                       | ` block, so the workflow file was invalid and CI started no jobs until a human reported it.                                                                                              | `AGENTS.md`: check that a workflow file parses before pushing it, and look at the CI run on that push. |
| #23 | The federated credentials used the name-based OIDC subject, but this repo's tokens carry owner and repository IDs, so Entra rejected every run.                                                                                   | `infra/envs/shared/github.tf`: a comment says the subject must match exactly and where to find the format a run presents (the `AADSTS700213` error).                                     |
| #23 | Pull requests were mapped to the identity that can write staging, DNS and state, so a PR could change the workflow and use those rights.                                                                                          | `infra/README.md` and `github.tf`: pull requests get a separate read-only identity, and the `staging` environment is limited to `main`.                                                  |
| #28 | A comment copied the style of the surrounding code and cited a grilling question number (`Q38`), which tells a later reader nothing; the review had to ask for it to go.                                                          | `AGENTS.md`: comments state the reason in words and never cite a question number; name the document if a source is needed.                                                               |
| #28 | The staging apply failed after merge: the new Log Analytics workspace needs the `Microsoft.OperationalInsights` namespace, which the subscription had not registered and CI's identity can't register, and no plan can show that. | `infra/envs/staging/versions.tf` registers the namespace; `infra/README.md`: register it once by hand before the first apply.                                                            |
| #27 | The layer rules allowed imports the decision doesn't name (`routers → domain`, `services → prompts/db`) until Copilot flagged them.                                                                                               | `.oxlintrc.json`: a comment states the import graph, and `layers.test.ts` probes every allowed import and a representative set of forbidden ones.                                        |
| #27 | Code comments and lint messages cited a bare "Q46", which a reader of a lint error can't look up.                                                                                                                                 | Covered by the #28 rule in `AGENTS.md`: comments never cite a question number.                                                                                                           |
| #27 | A nested `.oxlintrc.json` with `extends` silently dropped the root's `apps/**` override, and a lookahead regex in `no-restricted-imports` silently matched nothing.                                                               | `AGENTS.md` tooling notes: path-based overrides don't survive `extends`, and oxlint regexes have no lookahead.                                                                           |
